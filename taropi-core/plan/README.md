# Plan Workflow / 三阶段状态机

`/plan 任务描述` 将调研、确认和实施串成闭环。

1. **计划制定**：临时使用 `Aurum` 和只读工具调研代码。掌握背景后，若仍有不确定部分，主 Agent 会通过提问与用户反复确认；达到 99% 一致性后才输出带有 `Plan:` 的详细计划。
2. **澄清确认**：TUI 将计划写入固定目录 `.pi/taropi/plans/`，并直接展示完整文件地址。用户可选择开始实施，或输入补充内容后回到计划制定阶段。
3. **实施**：恢复进入 `/plan` 前的模型和工具，按确认的计划修改代码并执行必要校验。实施结束后，计划文件标记为已完成，原始模型和工具集恢复。

## 模块结构

```text
plan/
├── index.ts    # 状态机、运行时切换、命令和事件处理
├── prompts.ts  # 计划制定提示词
├── tui.ts      # 确认界面、固定位置的计划文件写入与地址展示
└── README.md   # 模块说明
```

## 计划文件

TUI 固定将计划文件写入当前工作目录下的：

```text
.pi/taropi/plans/计划标题-时间戳.md
```

确认界面会显示本次生成文件的绝对地址。文件名使用计划标题和时间戳，文件内容记录计划文本、创建时间、更新时间和当前状态。

## 会话恢复

状态机持久化使用 `plan-workflow`。恢复会话后流程保持空闲状态，并保留最近一次计划文件的记录；不会恢复中断的规划或实施轮次。
