# Plan Workflow / 会话级三态工作流

只有用户执行 `/plan 任务描述` 可以进入计划流程。模型可通过固定注册的 `plan` 工具提交、完成或退出，但不能自行进入。

## 状态与工具

| 阶段 | 默认模型 | 默认禁用工具 | 流转 |
|------|----------|-------------|------|
| 非 plan（idle） | 保持当前模型 | 无 | 只能由 `/plan` 进入 planning |
| 计划中（planning） | Au | edit、write | submit 经真实用户确认进入 implementing；exit 退出 |
| 实施中（implementing） | Ag | 无 | complete 完成；exit 退出 |

`Au/Ag` 使用已有模型别名配置，也支持 `Aurum/Argentum/Cuprum` 和 `provider/model-id`。进入 `/plan` 时直接切规划模型，不压缩；确认实施后先 compact，再切实施模型。退出或完成不切回旧模型。模型缺失、无凭证或切换失败时告警并沿用当前模型。用户中途手动切模型不被锁定，恢复时沿用 Pi 会话记录的模型。

工具声明始终不变，仅通过 `tool_call` 拦截。计划中可以使用 bash、查询或调研工具，但提示词明确要求**只能读，禁止实际修改本地或远程数据**。这不是只读沙箱，不解析 shell 命令做复杂校验；现有 permissions 规则继续生效。工作流自己保存 Markdown 是必要例外。

`plan` 的 action：

- `status`：返回当前阶段、规则、原始任务和完整计划；压缩或恢复后不确定阶段时可主动查询。
- `submit`：只在计划中接受包含编号步骤的完整计划，先保存正文，保存成功后按明确的计划标题同步文件名，再使用 Pi 原生选择框询问“开始实施 / 补充内容 / 暂不决定”，显示计划文件路径。选择补充后关闭选择框并结束本轮，用户从真正的主输入框补充；不再弹出简易输入框或自动生成空补充。选择补充计一次调整轮数。Esc、Ctrl+C、“暂不决定”及确认中断都是正常取消，保持计划中，不增加调整轮数。TUI 和 RPC 都使用 select，RPC 补充由客户端原有输入界面提交；无 UI 时不能批准实施。
- `complete`：只在已启动的实施阶段接受结果、验证与风险摘要，文件标记 completed 并回到 idle。
- `exit`：模型根据用户的自然语言退出请求调用，文件标记 exited 并回到 idle。

确认后直到实施提示实际送达之前，仍沿用计划阶段工具管控，防止同批后续写工具提前执行。`submit` 确认结果不内嵌实施提示；本轮完全收尾后，通过 compact 回调下发一次。取消压缩时保留待启动检查点，等用户再次输入；非取消的压缩失败告警后允许降级启动。

## Markdown 持久化

状态与正文在同一个文件，不创建额外状态 JSON，也不写会话 custom 条目。`/plan` 先用规划配置模型（解析失败时用当前模型）发起一次独立的短标题概括请求，把当前参数和当前分支的最近可见会话文本作为命名数据，不携带工具、不切换主会话模型、不把辅助请求或响应写入主会话历史。参数是“按这个方式、输出计划”等指代性话语时，应结合最近讨论概括实际工作主题；参数明确提出新任务时，以新任务为准。

上下文只提取用户／助手文本、分支摘要与最新压缩摘要，忽略图片、思考、原始工具参数／结果、系统提示及 custom 条目。最近文本从后向前选取，恢复顺序后发送；压缩摘要最多 2000 个 Unicode 字符，上下文总计最多 8000 个 Unicode 字符，不重新发送最新压缩前的原始历史。没有上下文或读取失败时，只使用当前任务（读取失败告警）。标题最多 20 个 Unicode 字符，清理 Markdown 标记、非法字符及冗余分隔符。模型失败、无凭证、空/非法输出或 15 秒超时时，告警并回退到任务首个非空行，清理后为空使用 `plan`。辅助请求会增加一次模型调用的延迟、token 与费用，最近会话文本会发送给配置的规划模型，其 provider 可能与当前主会话不同。

TUI/RPC 在等待标题时显示原生选择框，可选“取消创建”，Esc/Ctrl+C 同样取消；会话切换、关闭或新的用户输入也使旧请求失效。取消不执行失败回退，不创建文件或进入 planning。无 UI 时仍支持生命周期和已有运行信号的取消。辅助请求不支持取消的 provider 可能继续处理远程请求，但其过期结果不会创建文件。

标题确定后捕获本机日期时间，排他创建：

```text
.pi/taropi/plans/<短标题>-YYYY-MM-DD-HH-mm.md
```

例如 `精简计划文件-2026-10-21-23-30.md`。日期和分钟使用本机时区，时间分隔符采用 `-`（冒号不兼容 Windows 文件名），不包含秒、毫秒或随机后缀。同一分钟、同一最终清理标题如已有文件（包括其他会话、已完成/退出历史或符号链接），拒绝创建，保持 idle；用户需更换任务名称或下一分钟重试，不自动加序号或重新生成标题绕过冲突。这里按文件名判重，不按任务语义判重；时区变更或夏令时回拨遇到已有文件时也拒绝创建。

入口名称是临时概括名。每次 planning 阶段 `submit` 正文保存成功后，从明确的“计划标题：”（兼容“标题：”）提取名称，沿用相同的清理和 20 字符上限，同步为 `<计划简要标题>-YYYY-MM-DD-HH-mm.md`；时间始终取 frontmatter 的首次 createdAt，按本机时区格式化，而不是提交时间。缺少／非法标题、目标路径不变时不改名，不拿“目标”字段代替明确标题。标题修订后再 submit 会跟随改名，确认实施后、完成／退出和恢复均不改名，不批量迁移历史文件。确认框、submit 工具结果及后续阶段消息显示当前路径，不改写历史里出现的旧路径。外部编辑器打开的旧路径需要重新打开。

文件名不编码状态；完整原始 `/plan` 参数仍保存到 frontmatter，不被标题或上下文替代。文件头示例：

```markdown
---
schema: 1
sessionId: "会话 ID"
status: "planning"
task: "原始任务"
adjustmentRounds: 0
pendingLaunch: false
createdAt: "2026-10-20T00:00:00.000Z"
updatedAt: "2026-10-20T00:00:00.000Z"
---

# 任务摘要或计划标题

## 计划详情

尚未提交
```

frontmatter 值按 JSON 字符串、数字和布尔序列化为合法 YAML，正文不重复状态和时间字段。首次创建先写同目录完整临时 Markdown，再用 hard link 原子排他发布，失败清理临时文件且不覆盖目标；权限或文件系统能力不支持时报告失败，不退化为覆盖写入，也不允许仅内存中的新活动计划。创建成功后，每次正文更新仍先写同目录临时文件再 rename，失败时保留原文件、告警，内存流程继续，submit 不改名。正文保存成功后的改名先用 hard link 排他链接到新名称，再 unlink 旧路径，成功后更新内存路径。目标已存在（包括其他会话、历史和符号链接）或文件系统失败时保留原名并告警，不覆盖、不追加后缀，不阻断用户确认。旧路径 unlink 失败会尝试回滚同 inode 的目标链接；回滚失败或进程在 link/unlink 之间崩溃时可能残留两份同内容文件，需要人工检查清理，恢复不会自动清理副本。此时重启可能恢复旧检查点，尤其终态写入失败时可能重新发现旧活动计划。完成摘要另外保存到正文“实施结果”。

恢复会话或 `/reload` 时，扫描 `.md` 的 frontmatter，按 sessionId 匹配 planning/implementing，取 updatedAt 最新的有效文件（同时间按路径排序），再读取所选正文。无 frontmatter 的旧文件、临时文件、损坏或 schema 不匹配文件跳过；completed/exited 保留为非活动历史。扫描随文件数量线性增长。

## 中断与恢复

- Agent 正常停止、模型报错、Ctrl+C 中断和退出进程，都不自动完成或清空计划。
- 取消决策或选择补充后，保留已提交正文、planning、当前模型和工具策略；不压缩、不切模型、不自动发请求。工具会使用会话中断 API 停止当前运行，避免同批其他工具或排队消息绕过单个结果的 terminate。TUI 沿用 Pi 的中断行为，把排队文本恢复到主输入框并保留已有草稿；RPC 没有主编辑器，排队文本的显示由客户端与 Pi 自身负责。
- 主输入框完全沿用当前编辑器：多行／图片粘贴、光标移动、撤销、历史、补全和外部编辑器不再由 plan 仿制。原生选择框使用 tui.select.* 快捷键，选“补充内容”后才进行输入。
- 确认真正收到中断信号时，Pi 本身可能显示 Operation aborted；这不表示 plan 失败或退出。过期会话的决策被忽略，不中断新会话。
- 恢复只还原阶段、工具策略和 HUD，并提示一次，不自动发模型请求；下一次用户输入沿原阶段继续。
- `/archive` 或其他方式重建同 id 会话后，若当前 header.timestamp 晚于活动 plan.createdAt，plan 自行标记 exited、清除 pendingLaunch 并保持 idle，正文保留。保存失败时告警且当前仍保持 idle；系统时钟回拨可能漏判。
- 确认后若在实施提示送达前退出，pendingLaunch=true；恢复后的下一条输入合并一次实施规则、完整计划与用户输入。之后普通输入不再拼接规则。
- 未确认计划依赖 Pi 会话历史恢复调研上下文；Markdown 保留原始任务和最近提交正文。实施中断后先检查已有副作用，不能盲目重放工具。
- 不迁移旧 `plan-workflow` 会话条目。fork/clone 的 sessionId 不同，不继承活动状态；同一 sessionId 的 tree 分支共享会话级检查点。

## 用户阶段配置

可选文件 `getAgentDir()/plan.json`，默认 `~/.pi/agent/plan.json`。该配置 JSON 不是状态文件，不会自动创建或写回。

```json
{
  "planning": {
    "model": "Au",
    "blockedTools": ["edit", "write"]
  },
  "implementing": {
    "model": "Ag",
    "blockedTools": []
  },
  "idle": {
    "blockedTools": []
  }
}
```

每个阶段支持 `model`、`blockedTools`、`prompt`。prompt 完整替换默认阶段规则，任务、计划正文和路径仍由代码附加；应自行保留只读、确认和完成约束。model=null 关闭该阶段自动切换；idle 保持当前模型，不使用 model。blockedTools 是完整替换而非追加（空数组关闭该阶段拦截），不建议禁用 plan，否则模型无法流转。字段缺失或非法独立回退，配置缺失/损坏使用默认值。会话启动、恢复或进入 `/plan` 时重读配置，中途修改用 `/reload` 生效。

## 缓存边界与验证

每次阶段流转仅下发一次规则：/plan 用户消息、compact 后实施用户消息、complete/exit 工具结果。没有 `before_agent_start`、`context`、`turn_end` 注入，也不更改系统提示或工具列表。

进入 /plan 切 Au 可能使第一次请求 cache miss；确认后的切 Ag 与 compact 的前缀重建处于同一个阶段边界，但 compact 本身还会产生一次摘要请求。手动切模型也可能 miss。阶段内历史只追加，不保证不同 provider 的实际缓存命中。自动压缩可能摘要掉阶段规则，需要模型主动调用 status。

相邻 Vitest 测试覆盖配置、带上下文短标题、Unicode 上限与压缩边界、文件命名、排他发布／改名、改名冲突及回滚失败、Markdown、流转、取消、失败降级及真实 AgentSession。SDK 使用模拟 provider 与模拟压缩结果，不访问真实用户配置或网络；分别记录标题辅助请求与主会话请求，断言聊到一半切 /plan 时辅助请求包含实际讨论内容但不进入历史，submit 改名后阶段内请求前缀仍只追加、单次实施启动、模型切换和会话恢复。**发布前仍需真实 API 核对 cacheRead，SDK 通过不等于缓存验证通过。**

## 模块结构

- index：注册命令、固定工具、生命周期和 HUD。
- workflow：会话检查点、流转、异步启动与过期回调防护。
- types / config / prompts：类型、独立阶段配置和一次性规则。
- file：Markdown 元数据、确定性文件名、排他发布／改名、原子正文写入和扫描恢复。
- runtime / title：阶段默认模型解析和 plan 标题封装；只读会话文本提取、独立标题请求与文件名清理复用公共 title 模块。
- tool / tui：模型工具契约及原生选择交互，补充回主输入框。

临时体验（在仓库根目录执行，避免重复加载安装版扩展）：

```bash
pi -ne -e ./taropi-core/index.ts
```
